Set up FeurTube

FeurTube patches a supported YouTube APK on your computer. There is no public prepatched APK.

Sign-in requires ReVanced GmsCore, a separate microG-based app that participates in Google authentication. Read the trust notes before adding an account.

Compatibility

YouTube APKUpstream Android minimumFeurTube status
21.13.164Android 9Accepted; no device test
21.39.525Android 12LExperimental; tested on Android 16

Testing with 21.39.525 on a Samsung S23 Ultra confirmed Shorts hiding, shared Shorts in the regular player, Premium background playback, native downloads, offline playback and default link routing. Other devices and full Premium compatibility are untested, including PiP, casting and enhanced bitrate.

Use a standalone, Google-signed APK. Split APKs and APKM, XAPK or APKS bundles are unsupported. The patcher rejects unsupported versions and signing certificates.

Build from source

On your computer, install Git, Python 3.11+, JDK 21, and Android SDK build-tools 34.0.0. Linux and macOS are supported. Set JAVA_HOME and ANDROID_HOME to the JDK and SDK directories. Patching can use up to 4 GB of Java heap.

Where do I set those paths?

Set them in the terminal you use to build. Replace these example paths with your own installations:

export JAVA_HOME="/path/to/jdk-21"
export ANDROID_HOME="/path/to/android-sdk"

In Android Studio, open Tools → SDK Manager to find the SDK location. Under SDK Tools, enable Show Package Details and select build-tools 34.0.0.

Check your tools

git clone https://github.com/sal0-h/feurtube.git
cd feurtube
./feurtube doctor
./feurtube bootstrap
./feurtube test

doctor checks Python, JDK 21 and the SDK tools without downloading or changing anything. Fix any reported problem before continuing.

Sign and patch

Generate your signing key once. The command asks for a password privately and confirms it before creating the key:

./feurtube keygen

Patch your supported APK, entering the same password when asked:

./feurtube patch /path/to/youtube-21.39.525.apk --experimental

For 21.13.164, change the input path and omit --experimental. Noninteractive builds can supply FEURTUBE_KEYSTORE_PASSWORD through their environment.

The output is dist/feurtube.apk, with a JSON build receipt beside it. Both are written after the signed APK passes verification; existing files are not overwritten. Patch logs remain under build/patch-*.

The tests exercise the extension DEX and Morphe loader. They do not establish Android or playback compatibility. Downloads are pinned in upstream.lock.json; those upstream binaries are not rebuilt from source.

Install and sign in

  1. Install ReVanced GmsCore from its official releases.
  2. Transfer dist/feurtube.apk to your phone and install it. If Android asks, allow installation from the app you used to open the file; revoke that permission afterward.
  3. Open FeurTube and complete sign-in on your device.

The package is app.feurtube.android, so you can keep stock YouTube installed. Shorts hiding is enabled on a fresh install. Its settings are under FeurTube in the app’s settings. Stream spoofing defaults to off.

Find the settings

From YouTube’s Settings page, select FeurTube. Shorts hiding is already on for a fresh install. The controls are here:

  • Shorts → Shorts player → Enable hiding Shorts shelves controls feed shelves. Individual shelf filters are listed below it.
  • General → Navigation bar → Hide Shorts button controls the bottom tab.
  • Shorts → Shorts player → Shared Shorts describes the regular-player link behavior.

Menu wording can vary by language. Existing saved settings take precedence over defaults when you update.

Open YouTube links

In Android settings, open Apps → FeurTube → Set as default (sometimes called Open by default). Enable Open supported links for youtube.com, www.youtube.com, m.youtube.com and youtu.be.

If stock YouTube owns those links, turn off its supported-link handling first. You do not need to uninstall it. Some chat apps use their own browser; choose their option to open the link externally. Shared Shorts should open in the regular video player.

Updates

Back up .cache/signing.p12 and its password privately. Every update must use the same key. Keep that directory when updating the source, then rebuild with a supported APK and a new output path:

git pull --ff-only
./feurtube test
./feurtube patch /path/to/youtube-21.39.525.apk --experimental --output dist/feurtube-next.apk

Install the new APK over your existing FeurTube installation. Never regenerate the key to resolve an update error.

Do not force a new YouTube version through the patcher or install the result of a failed patch. Check the README for version changes.

Trust and privacy

You are trusting FeurTube, RVX, Morphe and GmsCore, as well as the original YouTube app. GmsCore runs beside Google Play Services and handles authentication and tokens for the modified app. Local builds help you inspect the patching process; they do not prove every dependency is safe. Report security vulnerabilities through GitHub’s private reporting form.

FeurTube adds no analytics service or project login. YouTube and its dependencies still communicate with Google. This website uses no analytics, cookies or third-party fonts; hosting requests are handled by GitHub Pages.

Troubleshooting

JDK 21 or SDK tools are missing

Run ./feurtube doctor. Set JAVA_HOME to a full JDK 21, not a JRE. Install SDK build-tools 34.0.0 even if a newer version is already installed, and point ANDROID_HOME at the SDK root.

The build rejects my APK

Check its exact version and that it is a standalone APK. Do not edit the compatibility check. A checksum error for a downloaded tool needs investigation before replacing the pinned hash.

Android refuses an update

Check that you used the same signing key. A differently signed APK cannot update the existing installation. Do not remove an app or clear its data just to make a test pass.

Shorts are still visible or playback fails

Check the FeurTube settings and report the exact surface, YouTube version and Android version using the app bug form. The initial device test does not cover every playback mode or entry point.

I need help building or installing

Use the build and installation form. Include the command that failed, your computer’s OS and the error message. Keep APKs, signing keys, account details, tokens, raw phone logs and authentication screenshots private.
